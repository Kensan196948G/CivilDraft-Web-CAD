# Phase 0 性能ベースライン

対象: `Civil-Draw`（Kensan196948G/Civil-Draw、HEAD `ad76b9b`）。要件定義書§22の実装成果物「基準性能」、§19 R-005への対応。

方針: Phase 1でCivilDraft側にCIベースの性能回帰テストを新設する際の**出発点**として、Civil-Draw時点で「実際に何が測定されており、何が測定されていないか」を正直に記録する。未測定を測定済みであるかのように扱わない。

## 実装済みで有効と確認された最適化

| 項目 | 内容 | 継承判定 |
| --- | --- | --- |
| R-tree空間索引 | rbushラッパー（spatialIndex.ts）による当たり判定・選択範囲検索の高速化 | as_is（[ADR-0008](../../adr/0008-spatial-index-per-drawing-instance.md)でシングルトン構造のみ改修） |
| Konva 4層分離 | 背景・図形・選択・UI層を分離しdirty領域の再描画を最小化するCanvas描画パイプライン | as_is |
| ビューポートカリング | 画面外図形の描画スキップ | as_is（メイン描画パスのみ、Minimapは未適用） |

## 未測定・未検証の項目（Phase 1で再測定が必要）

| 項目 | 現状 | 対応方針 |
| --- | --- | --- |
| Minimapのカリング | 画面外図形も含め全図形を毎フレーム描画しており、ビューポートカリングの対象外 | Phase 1でMinimap再設計時にカリング適用を設計に含める |
| ベンチマーク図形の代表性 | ベンチマークで使用される図形種別が全14種中4種のみに限定されており、実運用（土木図面特有のハッチング・引出線・多角形密集等）を代表していない | CivilDraft側のベンチマークは実際の土木図面サンプルから抽出した図形種別構成で再設計する |
| 10,000図形時のメモリ使用量 | 未計測。fps等の速度指標のみが記録されており、メモリプロファイルは存在しない | Phase 1のE2E性能テストにメモリ計測（`performance.memory`相当）を追加 |

## 重大な発見: E2E性能回帰ガードの無力化（要修正確認事項）

`e2e/perf.spec.ts`のfps閾値アサーションが、コミット`1f93474`（2026-05-18、コミットメッセージは本変更と無関係な内容）において、`avgFps > 25`（複雑図面）/`avgFps > 50`（単純図面）相当の基準から**`minFps > 1`**へ変更されていたことをPhase 0調査で確認した。

- `minFps > 1`は「1フレームも完全停止していない」ことしか保証せず、実質的に性能回帰を検出できない閾値である
- ドキュメント（PERF_REPORT.md等）側は変更前の基準値を性能保証の根拠として記載し続けており、**テストが無力化された事実が文書に反映されていない**（[リスク台帳](./risk-ledger.md) R-010の一種）
- 変更理由を示すコミットメッセージ・PR説明・Issueへの言及は確認できず、意図的な性能基準緩和か誤操作かは不明（Phase 0の調査範囲では原因特定不可、`open_questions`として残す）

**Phase 1での対応方針**: CivilDraft側のE2E性能テストは、この経緯を踏まえて新規に基準値を設定し直す（Civil-Draw時点の`avgFps>25/50`をそのまま信頼せず、CivilDraftの実際のCanvas実装で再計測してから閾値を確定する）。CI上で閾値を弱める変更が発生した場合に検知できるよう、性能テストの閾値変更はコードレビューで明示的に指摘する運用（[ADR-0010](../../adr/0010-ci-quality-gate-enforcement.md)）に含める。

## 未解決の技術的疑問（open_questions、要検証）

- `dxf-writer`の`setUnits('Meters')`呼び出しが、内部的に座標値を自動スケーリングするのか、単にDXFヘッダーのメタデータを書き換えるだけなのかが未確認（Phase 0調査時点でscratchpadクローンに`node_modules`未インストールのため、ライブラリ内部実装を検証できなかった）。[ADR-0005](../../adr/0005-unit-safe-coordinate-values.md)の実装時に確定させる
- 複数図面の同時編集要件の有無が、`layerStore`/`spatialIndex`のインスタンス粒度設計（ドキュメント単位か、アプリケーション単位か）に直結するため、Phase 1着手前に要件を確定する必要がある

## Phase 1でのベースライン再設定方針

1. CivilDraft側の実装（React 18/19系、Konva、rbush継承）で、代表性のある図形セット（土木図面から抽出）を用いて初回計測を実施
2. 計測結果を本ドキュメントの後継として `docs/testing/performance-baseline.md`（詳細設計仕様書§2のディレクトリ構成準拠）に記録
3. E2E性能回帰テストの閾値は「初回計測値の一定割合（例: 80%）を下回ったら失敗」という相対基準で設定し、Civil-Draw同様の無力化が再発しないようレビュー必須項目とする
