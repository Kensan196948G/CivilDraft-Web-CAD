## 主要な結論（サマリー）

1. **型システム三本柱（Brand ID型・Result&lt;T,E&gt;・単位付き座標値）は全て新規設計が必要**。Civil-Drawはこれらを一切採用しておらず、部分修正での解消は不可能と判定した（cross_cutting_risks #1）
2. **土木属性・数量算出・施工ステップ・図面改訂履歴は実装が存在しない**（grep 0件）。要件定義書§17.2の新規設計対象方針が実装調査により裏付けられた
3. **Docker前提のデプロイ資産はCivilDraft標準スタック（Systemd + GitHub + Cloudflare + Neon）と非両立**であり、全て新規設計する（[ADR-0006](../adr/0006-deploy-stack-systemd-cloudflare-neon.md)）
4. **文書と実装の乖離パターン（R-010）が複数箇所で反復顕在化**。特にE2E性能回帰テストの閾値が実質無力化されていた事実は、CI品質ゲートの実効性検証を制度化する必要性を示す（[ADR-0010](../adr/0010-ci-quality-gate-enforcement.md)）
5. **権利面（ライセンス）は良好**。389解決パッケージにコピーレフト系混入なし。運用面（NOTICE不在、二重ロックファイル）には軽微な負債がある
6. **性能最適化の核（R-tree空間索引、Konva 4層分離、ビューポートカリング）は高品質でas_is/modify継承可能**。ただしグローバルシングルトン構造は複数ストアで共通の設計負債であり、マルチドキュメント編集要件との整合を要する

## 未解決事項（Phase 1着手前に確定が必要）

- 複数図面同時編集要件の有無（`layerStore`/`spatialIndex`のインスタンス粒度設計に直結、[ADR-0008](../adr/0008-spatial-index-per-drawing-instance.md)）
- `dxf-writer`の`setUnits('Meters')`が座標値を自動スケーリングするかの実装確認（[ADR-0005](../adr/0005-unit-safe-coordinate-values.md)）
- E2E性能回帰ガード無力化（commit `1f93474`）の原因（意図的な緩和か誤操作か、Phase 0調査範囲では特定不可）
