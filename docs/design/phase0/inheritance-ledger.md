# Phase 0 継承台帳（Inheritance Ledger）

- 対象: `Civil-Draw`（origin: Kensan196948G/Civil-Draw、branch main、HEAD `ad76b9b`、2026-06-13時点、336コミット）
- 根拠: 要件定義書§7.5「継承判定基準」の6観点（権利・品質・保守性・セキュリティ・性能・適合性）による棚卸し
- 実施方法: Dynamic Workflow（6観点並列調査エージェント + 統合エージェント、計7エージェント、総トークン1,010,923・総ツールコール267）
- 統合判定原則: いずれか1観点でもdiscard相当の重大な問題（権利不明、致命的脆弱性、新データモデルと根本非両立）があれば、他観点が良好でも最終判定はdiscardまたは大幅modifyとする。適合性観点で「型定義そのもの」が非両立でも、配下のアルゴリズム・ロジックは別コンポーネントとしてmodify継承の余地を判定する。
- コンポーネント総数: **46**（as_is 11 / modify 20 / reference_only 8 / discard 7）

## 判定区分の定義（要件定義書§17.1準拠）

| 判定 | 意味 |
| --- | --- |
| `as_is`（そのまま継承） | 変更なしでCivilDraftへ持ち込む |
| `modify`（改修して継承） | 設計思想・アルゴリズム・パターンは継承するが、型・構造・保存先等を新データモデルに合わせて改修する |
| `reference_only`（参考のみ） | 実装は持ち込まないが、設計意図・チェック観点・概念モデルとして参照する |
| `discard`（廃止） | 新規に設計・実装する。既存資産は一切継承しない |

## 横断的リスク（cross_cutting_risks）

個別コンポーネントの修正では解消できない、リポジトリ全体の設計方針レベルの課題。詳細は [risk-ledger.md](./risk-ledger.md) を参照。

1. 型システム三本柱（Brand ID型・Result&lt;T,E&gt;・単位付き座標）がリポジトリ全体で不採用 — 部分的置き換えでは解消できず、全面移行が前提
2. Dockerを前提としたデプロイ資産一式がCivilDraft標準スタック（Systemd+Cloudflare+Neon）と全面非両立
3. 静的ドキュメント（SECURITY_AUDIT.md/PERF_REPORT.md/CHANGELOG.md/ISO27001_COMPLIANCE.md）と実装の乖離パターン（R-010）が複数コンポーネントで反復検出
4. autosave・監査ログ・スナップショット等、複数機能がlocalStorage構造的依存を持ち、IndexedDB/Neonへの移行が横断的に必要（R-006）
5. layerStore/canvasStore/toolStore/spatialIndex等、モジュールレベルのグローバルシングルトンパターンが複数箇所で採用（単一ドキュメント・単一タブ前提）
6. 「10,000図形で60fps」「カバレッジ100%」等の指標は測定範囲が限定的で、そのまま新システムの目標達成保証根拠にできない
7. 認証アーキテクチャ（msal-browser）はCloudflare Accessモデルと構造的に非両立。フォルダ分離パターンのみ参考可
8. package-lock.json/pnpm-lock.yaml二重管理、OSSライセンスNOTICE不在が技術的負債として残存
