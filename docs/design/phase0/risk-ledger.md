# Phase 0 リスク台帳（Risk Ledger）

要件定義書§19（リスクと対策）のR-001〜R-010に対し、Civil-Draw 6観点棚卸し（Dynamic Workflow実行、2026-07-15）で得られた具体的な実測・実装エビデンスを反映する。要件定義書側は変更しない（正本は要件定義書§19）。本台帳はPhase 0時点の**実証状況**を追記するトレーサビリティ台帳として運用する。

凡例: `顕在化` = 具体的な実装事例で確認された / `裏付け` = リスクの想定通りの状況を確認した / `未検証` = Phase 0の調査範囲外で確認できていない

## Phase 0で新たに確認された固有の技術的発見（要件定義書のR-IDに対応しない事項）

要件定義書のリスク一覧はプロジェクト開始前に想定されたリスクのため、実装詳細までは踏み込んでいない。Phase 0調査で判明した、次フェーズの設計判断に直接影響する具体的事実を記録する。

- **認証モジュールは「未実装」ではなく「実装済みだが無効化」**: CHANGELOGは認証機能を「未実装」と記載しているが、実際にはMSAL/Entra ID統合コードは完成しており、ITがEntra IDテナントIDを未発行のため`isAuthConfigured=false`で機能を無効化しているだけだった。ドキュメントの表現が実態と異なる（R-010の一種）。ただし認証アーキテクチャ自体はCloudflare Accessモデルと非両立のため、テナント登録が完了しても継承しない（discard判定は変わらない）
- **spatialIndex等のグローバルシングルトンパターン**: 性能面では極めて優秀（rbushラッパーで約700倍の高速化）だが、マルチドキュメント編集要件との構造的な衝突がある。性能の良さが適合性の問題を覆い隠す典型例であり、統合エージェントが「性能観点を適合性観点が上書きする」判断を行った
