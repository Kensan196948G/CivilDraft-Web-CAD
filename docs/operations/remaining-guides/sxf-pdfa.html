1. SXF(P21) 完全適合

1-1. 現状の実装（ここまで完成済み）

項目状態
ファイル形式ISO 10303-21（STEP P21）ヘッダ＋DATA セクション
スキーマ宣言FILE_SCHEMA(('SXF'))
対応図形LINE / POLYLINE / CIRCLE / TRIMMED_CURVE（円弧・PARAMETER_VALUE トリミング）
構造PRODUCT → PRODUCT_DEFINITION → PRODUCT_DEFINITION_SHAPE → SHAPE_REPRESENTATION → GEOMETRIC_CURVE_SET
出力導線印刷・出力画面の「SXF(P21) 試作」チェックボックス（src/domain/edelivery/sxfP21.ts）

1-2. 残っている作業（完全適合に必要な差分）

#作業内容
1属性エンティティの追加SXF 仕様の属性エンティティ（層情報・図面属性・縮尺・表題欄等。例: SXF 系の LAYER / ATTRIBUTE 相当）を DATA セクションへ出力する。
2CAD製図基準への適合レイヤー命名規則・文字スタイル・線種定義・縮尺表記・図枠/表題欄の表現を CAD製図基準（案）に合わせる。
3実データでの往復検証サンプル図面 → P21 出力 → 電子納品チェックシステム → 修正ループを回す。
4認証・文書化適合範囲（対応図形・非対応図形）を明記し、発注者仕様・適用版を管理する。
⚠ 属性エンティティの「正確なエンティティ名・属性名」は、国土交通省「電子納品等運用ガイドライン【土木工事編】」付属の SXF 仕様書（SXF P21 編）と電子納品チェックシステムで確認してください。ここでは構造の考え方を示します。

1-3. 実装の拡張イメージ（コード）

src/domain/edelivery/sxfP21.ts の exportSxfP21() に属性出力を追加する例:

// 出力イメージ（エンティティ名は発注者仕様・SXF 仕様書で確定すること）
// 1) レイヤー属性
// #N1=SXF_LAYER('S-仮設', ...);            ← 仮設レイヤー
// #N2=SXF_LAYER('S-土工', ...);
// 2) 図面属性（図面番号・縮尺・改訂）
// #N3=SXF_ATTRIBUTE('DRAWING_NO', 'DWG-014');
// #N4=SXF_ATTRIBUTE('SCALE', '1:500');
// #N5=SXF_ATTRIBUTE('REVISION', '3');
// 3) 図形へレイヤー属性を関連付け
// #M1=... LINE エンティティ ... SXF_LAYER_REF(#M1,#N1);

拡張時の注意:

  • エンティティ名・引数の並びは「SXF P21 仕様書」に厳密に合わせる。
  • 対応していない図形（楕円・スプライン・ハッチ・文字）は現状どおり警告としてスキップし、無効エンティティを出力しない。
  • 出力後に必ず電子納品チェックシステムでエラー 0 を確認する。

1-4. 検証フロー（電子納品チェックシステム）

  1. アプリの印刷・出力画面で「SXF(P21) 試作」にチェックを入れ、「出力を実行」で .P21 を保存する。
  2. 電子納品チェックシステム（受発注者向けツール。利用可能な場合は JACIC 等の検査ソフト）へ P21 を読み込む。
  3. 「図面管理ファイル」「フォルダ構成」「エンティティ」の各チェック結果を確認する。
  4. エラーが出た項目を sxfP21.ts に反映し、再度出力→チェックを繰り返す（最大 3 ラウンドを目安）。
  5. 全チェック合格後、チェック結果・版・適用基準（例: 令和5年3月版）を管理ファイルへ記録する。
⚠ 電子納品チェックシステムは発注者・地域により利用方法が異なります。必ず当該工事の発注者仕様を確認してください。

2. PDF/A 認証（ICC 埋め込み＋verapdf 検証）

2-1. 現状の実装

src/domain/pdf/pdfA.ts の applyPdfAMetadata() が以下を実施済み:

  • XMP メタデータ（pdfaid:part=1 / conformance=B、タイトル・作成者・日時）
  • OutputIntent（GTS_PDFA1・sRGB IEC61966-2.1 を宣言）
  • フォントは pdf-lib の fontkit サブセット埋め込みに依存

未実装: ICC プロファイル（DestOutputProfile）の埋め込みと、verapdf 等による第三者検証。

2-2. ICC プロファイルの埋め込み

  1. sRGB ICC プロファイル（sRGB IEC61966-2.1、約 3.2 KB）を用意する。公開プロファイル（例: カラーマネジメント団体・OS 付属の sRGB Color Space Profile.icm）を利用する。
  2. プロファイルを src/domain/pdf/assets/ 等へ配置し、TypeScript のバイナリ import（?arraybuffer）または base64 定数として読み込む。
  3. applyPdfAMetadata() 内で、ICC ストリームを埋め込み、OutputIntent の /DestOutputProfile へ参照を追加する（pdf-lib の低レベル API 使用）。
  4. PDF/A-1b では全フォント埋め込みも要件。pdf-lib 出力は通常サブセット埋め込みになるが、日本語フォント未注入時のフォールバック文字（代替描画）が残らないことを確認する。
⚠ 埋め込み後も「自己宣言」は変わりません。必ず 2-3 の verapdf 検証を通過させてください。

2-3. verapdf による検証

  1. verapdf を入手する（公式サイト verapdf.org のインストーラ。Java 11+ が必要）。
  2. 検証対象の PDF を生成（アプリの「PDF/A-1b 指向メタデータ付与」で出力）。
  3. コマンド例: 
    verapdf --format text --profile pdfa-1b civildraft-pdfa1b.pdf
  4. 出力の Validation Result を確認:
    結果意味
    CompliantPDF/A-1b 適合（このまま電子納品候補）
    Non-compliant不適合。失敗ルール名（例: 6.1.3-1）を確認して修正
  5. 失敗ルールの代表例と対処:
    失敗例対処
    ICC プロファイル不足（OutputIntent）2-2 の DestOutputProfile 埋め込みを実施
    透明（Transparency）使用PDF/A-1 では透明禁止。透かし・墨消しの opacity を 1 にし、ExtGState を除去
    フォント未埋め込み日本語フォントを常に注入（fontLoader）し、代替描画を無効化
    メタデータ不備XMP の pdfaid 宣言とドキュメント情報の整合を確認

2-4. Ghostscript による代替生成（変換ツールとして）

アプリ側で PDF/A を完全生成できない場合は、Ghostscript で後処理することもできます（内容が再処理されるため、ベクター品質の劣化やフォント差し替えに注意）。

# PDFA_def.ps は Ghostscript のサンプル設定（sRGB ICC パスを指定）
gs -dPDFA=2 -dBATCH -dNOPAUSE -dPDFACompatibilityPolicy=1 \
   -sDEVICE=pdfwrite -sColorConversionStrategy=RGB \
   -sOutputFile=out-pdfa2.pdf \
   -dPDFAConfigFile=/path/to/PDFA_def.ps \
   input.pdf
⚠ 変換後も必ず verapdf で検証し、電子納品要件（PDF/A-1b か 2b かは発注者仕様）に合うものを選んでください。
