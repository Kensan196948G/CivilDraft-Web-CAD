Neon 本番マイグレーション適用手順

対象: migrations 0003〜0007 ・ 更新日: 2026-08-10
← 索引へ戻る
この手順で行うこと: 本番 Neon（civildraft-production）の main ブランチへ、 0003_persistence_schema_drift_fix・0004_id_type_alignment・ 0005_export_jobs_object_provider_alignment・0006_audit_log_previous_hash_unique・ 0007_drawing_checkouts を適用します（0001・0002 は適用済み前提）。 スクリプトは適用済みマーカーを検査し、既適用のものは自動スキップします。

1. 前提確認

項目条件
接続手段Neon コンソール（console.neon.tech）へログインできること、または接続文字列を入手できること
psqlpsql --version で動作確認（PostgreSQL クライアント 13+）
適用スクリプトscripts/apply-prod-migrations.sh がリポジトリ main に存在すること
承認本番 DDL 適用の人間承認が得られていること（AGENTS.md §8.6 の決裁必須）

2. 接続情報の準備

2-A. 既存の接続文字列を使う場合（推奨・最簡易）

  1. Neon コンソール → プロジェクト civildraft-production → Branches → main → Connect を開く。
  2. 「Connection string」欄をコピーする（postgresql://<user>:<password>@<host>/<db>?sslmode=require）。
  3. この文字列は秘密情報として扱い、コマンド履歴・チャット・リポジトリへ残さない。
⚠ パスワードはコンソール上で「Reset password」を押すと再発行されます。既存の接続文字列（Worker のシークレット等）と異なる場合は、後述 5-D の Worker シークレット更新が必要になります。

2-B. 一時ロールを作って使う場合（本番パスワードを変えない安全な方法）

  1. Neon コンソール → main ブランチ → Roles → New role で cd_migrate_<日付> を作成。
  2. 作成したロールのパスワードを「Reset password」で発行し、接続文字列を作る。
  3. 適用完了後、手順 6 でこの一時ロールを削除する。

3. 適用前チェック（読み取りのみ）

スクリプトが自動でマーカー検査を行うため通常は不要ですが、念のため手動でも確認できます。

psql "$CIVILDRAFT_NEON_DSN" -v ON_ERROR_STOP=1 -c "
  SELECT EXISTS (SELECT 1 FROM information_schema.columns WHERE table_name='drawing_contents' AND column_name='content') AS m0003;
  SELECT data_type='text' FROM information_schema.columns WHERE table_name='projects' AND column_name='id' AS m0004;
  SELECT column_default LIKE '%unassigned%' FROM information_schema.columns WHERE table_name='export_jobs' AND column_name='object_provider' AS m0005;
  SELECT EXISTS (SELECT 1 FROM pg_indexes WHERE indexname='audit_logs_previous_hash_unique') AS m0006;
  SELECT EXISTS (SELECT 1 FROM information_schema.tables WHERE table_name='drawing_checkouts') AS m0007;
"

t が返る項目は適用済み（スキップ対象）、f/NULL が返る項目が今回の適用対象です。

4. 適用の実行

# リポジトリ root で実行
git checkout main && git pull

CIVILDRAFT_NEON_DSN='postgresql:' '//<user>:<password>@<host>/<db>?sslmode=require' \

5. 適用後検証

5-A. スキーマ検証（スクリプト内でも実施）

  1. drawing_contents.content 列が存在
  2. projects.id が text
  3. export_jobs.object_provider の既定値が 'unassigned'
  4. 索引 audit_logs_previous_hash_unique が存在
  5. テーブル drawing_checkouts が存在

5-B. 実データ件数確認

SELECT (SELECT count(*) FROM export_jobs) AS export_jobs,
       (SELECT count(*) FROM drawing_checkouts) AS checkouts,
       (SELECT count(*) FROM audit_logs) AS audit_logs;

実データ 0 件を確認（既存データへの影響なし）。

5-C. Worker 経由スモーク（本番 API）

  1. ブラウザで https://civildraft-web-cad.mirai-dx-platform.com を開き、Access ログインする。
  2. DevTools → Network から API リクエストの Cf-Access-Jwt-Assertion ヘッダー値をコピー（または Access Service Token を使う）。
  3. 下記で一覧 API が 200 を返すことを確認: 
    curl -sS -H 'Cf-Access-Jwt-Assertion: <JWT>' \
  https://civildraft-web-cad.kensan1969.workers.dev/api/v1/projects

5-D. 接続文字列を変更した場合のみ

一時ロールやパスワード再発行で Worker の接続文字列と異なる場合、Worker シークレットを更新し再デプロイします。

printf '%s' 'postgresql:' '//<新しい接続文字列>' | wrangler secret put CIVILDRAFT_NEON_CONNECTION
wrangler deploy
⚠ 接続文字列更新後は必ず 5-C のスモークで API が 200/401（fail-closed）になることを確認してください。失敗時は旧値へ戻して再デプロイします。

6. 一時ロールの削除（2-B を使った場合）

  1. 検証がすべて成功したことを確認。
  2. Neon コンソール → main ブランチ → Roles → cd_migrate_<日付> → Delete。
  3. 削除後、5-C のスモークをもう一度実行して問題がないことを確認。

7. 失敗時の対処・ロールバック

症状対処
ON_ERROR_STOP で途中停止各マイグレーションは BEGIN/COMMIT 単位なので、失敗したファイルはロールバック済み。エラー内容を確認し、原因を解消してスクリプトを再実行（既適用分はスキップされます）。
0006 の一意索引作成失敗（既存 previous_hash 重複）過去の並行分岐が存在。前進修正マイグレーションで重複解消後に再適用（migration 0006 冒頭コメント参照）。
Worker が 503（CD-SYS-002）接続文字列・シークレットの不整合。5-D を参照して旧値へ戻す。
業務データへの影響全マイグレーションは前方互換 DDL のみ（列削除なし）。影響が出た場合は docs/operations/rollback-procedure.md に従う。
