# ADR-0004: Undo/RedoはCommandパターンで再実装し、全スナップショット方式を廃止する

## Status

Proposed（Phase 0棚卸し由来、2026-07-15）

## Context

Civil-Drawの現行実装は`Shape[][]`（全図形配列のスナップショット）をUndo/Redo履歴として保持する方式である。この方式は図形数の増加に比例してメモリ使用量・スナップショット生成コストが増大し、詳細設計仕様書が想定する大規模図面（10,000図形規模）では性能・メモリの両面でスケールしない。また、土木属性・数量・施工ステップなど新規に導入される属性データがShape本体と一体でスナップショットされる設計は、属性のみの変更と幾何変更を区別できず、変更履歴（監査ログ）との整合も取りにくい。

## Decision

CivilDraftのUndo/RedoはCommandパターン（各操作を「実行」「取り消し」のペアとして表現するオブジェクト）で再実装する。Civil-Drawの`Shape[][]`スナップショット方式は継承しない（discard）。

## Consequences

- 個々の操作（図形追加・属性変更・移動等）が独立したCommandオブジェクトとなり、メモリ使用量は変更差分に比例する
- Commandの実行ログは監査ログ（[ADR-0009](./0009-audit-log-hash-chain-workers-neon.md)）の入力としても再利用できる可能性がある
- 既存のツール実装（描画ツール群）はCommand生成を伴うインターフェースへ書き換えが必要になる
